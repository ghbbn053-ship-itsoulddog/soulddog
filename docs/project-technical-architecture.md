# 学途智伴技术文档

## 1. 项目概述

`学途智伴` 是一个面向大学生的个人校园智能平台，目标不是做一个泛化聊天机器人，而是围绕学生真实的校园学习场景，构建一个连接教务系统、学习平台、个人知识库与智能服务能力的统一平台。

项目当前已经具备以下技术主链路：

- 教务系统登录与会话管理
- 多类教务数据查询接口
- 工作区与知识库基础能力
- 聊天接口与上下文增强能力
- 超星 / 雨课堂二维码接入基础
- MCP 能力输出与外部 Agent 接入机制

从工程定位上看，`学途智伴` 已经不再是单一“教务问答页面”，而是正在向“校园场景可扩展 Agent 平台”演进。

---

## 2. 技术目标

本项目的技术目标主要包括以下几个方面：

1. 为学生提供统一的校园智能入口
2. 将教务系统中的高频数据结构化并提供稳定调用能力
3. 将课程资料、笔记与个人知识沉淀到工作区知识库中
4. 让智能问答建立在真实校园数据和个人资料之上
5. 将平台能力以 MCP 方式输出给外部智能体调用
6. 在后续阶段支持更完整的学习平台接入、课程级 RAG 与长期学习支持

---

## 3. 总体架构

项目采用前后端分离架构，并在后端内部拆分为教务数据服务、知识库服务、学习平台服务、聊天上下文服务、MCP 服务与 Agent 接入服务。

从产品层理解，项目可以抽象为四层：

### 3.1 校园数据层

负责教务系统数据的获取、解析、缓存与结构化管理，主要覆盖：

- 个人信息
- 学籍卡片
- 成绩
- 课表
- 培养方案
- 学业进度
- 考试安排
- 选课信息
- 执行计划

### 3.2 学习平台连接层

负责连接在线学习平台，当前主要包括：

- 超星二维码登录
- 雨课堂二维码登录
- 课程信息同步基础
- 学习行为和状态记录基础

### 3.3 个人知识库层

负责工作区、课程资料和知识文档的沉淀与管理，支持：

- 工作区创建与管理
- 文本文档入库
- 文件上传入库
- 文档切块
- 轻量向量检索
- 知识图谱基础关系抽取

### 3.4 智能服务层

负责统一对外提供平台能力，当前主要包括：

- Web 端聊天接口
- 基于教务数据和知识库的上下文增强
- MCP 工具目录与 HTTP 工具调用
- 远程 MCP transport
- 外部 Agent Access Token 机制

## 7. 教务系统能力

教务系统能力是当前项目最成熟的业务能力之一，主要由：

- `backend/app/api/education.py`
- `scraper`
- `education_sync`
- `education_cache`

共同组成。

### 7.1 已支持的教务接口

当前项目已具备以下教务查询能力：

- `/api/user/info`
- `/api/user/card`
- `/api/grades`
- `/api/grades/all`
- `/api/schedule`
- `/api/training-plan/my`
- `/api/academic-progress`
- `/api/exam-schedule`
- `/api/teacher/search`
- `/api/course/search`
- `/api/course-selection`
- `/api/execution-plan`
- `/api/all-data`

### 7.2 技术实现方式

教务查询的核心流程为：

1. 前端或 Agent 发起请求
2. 后端根据用户名校验访问权限
3. 通过会话存储拿到对应用户的教务 session
4. 创建 `JwxtScraper` 实例
5. 调用对应抓取逻辑
6. 返回结构化结果

### 7.3 当前价值

这部分能力的价值在于：

- 解决校园高频信息查询问题
- 为聊天与 RAG 提供真实数据源
- 为后续平台能力开放奠定基础

## 8. 工作区与知识库系统

工作区和知识库系统是项目从“教务查询工具”走向“长期学习平台”的关键部分。

核心代码包括：

- `backend/app/api/workspace.py`
- `backend/app/api/knowledge.py`
- `backend/app/services/workspace_knowledge.py`
- `frontend/src/app/workspace/`
- `frontend/src/app/knowledge/`

### 8.1 工作区能力

当前已支持：

- 创建工作区
- 列出工作区
- 查看工作区详情
- 查看工作区图谱

工作区的作用是：

- 作为不同课程、项目、学习主题的容器
- 将文档与知识内容按上下文组织起来
- 为后续课程级学习支持提供隔离空间

### 8.2 文档入库能力

当前已支持两种方式：

1. 文本直接入库
2. 文件上传入库

上传文件后，服务会根据文件类型做基础解析，当前代码已经支持解析相关依赖的预留和实现，包括：

- PDF
- DOCX
- XLSX
- PPTX
- CSV
- 纯文本

### 8.3 知识切块与管理

知识库服务支持：

- 文档切块
- 文档统计
- 文档状态管理
- 文档 chunk 查看
- 文档删除

### 8.4 知识图谱基础

工作区知识库服务还包含轻量关系抽取逻辑，当前可识别例如：

- 文档中提到 `skill`
- 文档中提到 `mcp`

虽然当前只是基础版，但这说明项目已经在往“结构化知识空间”演进，而不是只做文件堆积。

## 9. 聊天与上下文增强能力

聊天接口位于：

- `backend/app/api/chat.py`

该模块不是简单转发用户问题，而是已经具备一定程度的上下文增强与场景判断逻辑。

### 9.1 当前能力

聊天服务当前支持：

- 根据问题识别教务相关意图
- 从教务数据中构建上下文
- 从工作区知识库中检索补充信息
- 从学习记忆中构建额外上下文
- 针对部分问题生成 grounded answer

### 9.2 已有特征

当前聊天模块已经具备以下能力特征：

- 识别成绩、课表、考试、培养方案等问题类型
- 推断学期过滤条件
- 对“我是谁”“我在哪里上课”等问题进行专门处理
- 接入工作区知识库搜索结果
- 接入学习疑问和学习盲点上下文

### 9.3 当前边界

当前聊天能力已经有较强的平台感，但还未完全形成成熟的课程级 RAG 闭环。后续可以继续加强：

- 更完整的知识库召回与重排
- 学习状态驱动的问答策略
- 基于课程画像的持续学习支持

## 11. MCP 能力与工具开放

MCP 是当前项目最有平台差异化的部分之一。

- `backend/app/api/mcp.py`

### 11.1 MCP 的定位

在本项目中，MCP 不是单纯技术概念，而是平台能力对外开放的标准方式。

它承担的作用包括：

- 将平台内部能力标准化
- 供 Web 端查看和管理工具目录
- 供外部 Agent 调用平台能力

### 11.2 当前 MCP 能力

当前代码已体现出以下能力：

- 工具目录管理
- 工具 schema 获取
- HTTP 工具调用接口
- 工具探测接口
- Agent 可见工具目录
- 远程 MCP transport 支持

### 11.3 工具内容

从工具定义和能力前缀来看，当前 MCP 能力主要覆盖：

- 成绩相关查询
- 课表相关查询
- 学业进度相关查询
- 培养方案相关查询
- 考试安排相关查询

### 11.4 当前价值

这部分能力使项目从“Web 应用”扩展为“校园智能能力提供者”，也是与普通校园问答页面最明显的区别之一。

## 12. Agent Access 与外部智能体接入

相关模块：

- `backend/app/api/agent_access.py`
- `backend/app/services/agent_access.py`
- `docs/AGENT_MCP_INTEGRATION.md`
- `backend/mcp_agent_bridge.py`

### 12.1 设计原则

外部 Agent 不直接登录教务系统，而是复用 Web 平台已经完成的登录与授权状态。

这意味着：

1. 教务系统登录统一在 Web 端完成
2. 平台持有用户教务 session
3. 平台为用户生成 Agent Token
4. 外部 Agent 通过 Token 访问平台能力

### 12.2 当前能力

当前已经支持：

- 查看 Agent Token 列表
- 创建 Token
- 撤销 Token
- 查看服务绑定
- 获取 bootstrap 配置
- 为 Claude Desktop / OpenClaw 提供接入示意配置

### 12.3 技术价值

这一设计有三个价值：

1. 避免把教务账号暴露给外部 Agent
2. 让平台成为统一身份与能力中心
3. 为后续多服务、多 Agent 协作提供基础

---

## 13. 安全与隔离机制

当前项目已经在多个位置体现了安全和隔离设计。

### 13.1 用户名隔离

多个 API 在入口层使用 `enforce_username_isolation`，确保用户只能访问自己的数据。

### 13.2 Agent Token 鉴权

远程 MCP 与 Agent 接口需要通过有效 Token 才能调用。

### 13.3 服务绑定校验

当某些能力依赖教务绑定时，系统会校验对应绑定状态，不满足条件则拒绝调用。

### 13.4 会话统一管理

教务系统的真实登录会话由平台统一维护，而不是分散暴露给外部客户端。

这些设计为后续多用户、多 Agent、多服务并存提供了基础保障。

---

## 14. 当前项目边界

虽然项目已经具备较完整的技术雏形，但仍然需要明确当前边界：

1. 教务查询能力相对成熟，学习平台能力仍处于接入与同步基础阶段
2. 工作区与知识库能力已经具备，但课程级 RAG 闭环仍需继续完善
3. MCP 与 Agent Access 已有较强基础，但完整的插件生态与多 Agent 编排尚未完全落地
4. 平台已经具备产品化趋势，但仍处于持续迭代阶段

明确这些边界很重要，因为比赛材料、技术交接和团队内部沟通都需要区分：

- 已实现能力
- 正在建设能力
- 后续规划能力

## 16. 总结

从技术角度看，`学途智伴` 已经具备以下特征：

- 它不是简单的教务查询网页
- 它不是单纯的大模型聊天应用
- 它不是只做文档上传的知识库页面

它当前正在形成的是一个以学生个人校园学习场景为中心的智能平台：

- 底层有教务数据能力
- 中间有学习平台与知识库能力
- 上层有聊天、MCP、Agent 接入能力

这使它具备继续向“校园个人智能中枢”甚至“校园可扩展 Agent 平台”发展的技术基础。
